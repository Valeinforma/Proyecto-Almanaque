Technical Design Document
Versión: 1.0
Fecha: 24/09/2026

1. OBJETIVO
TechFix Manager es un sistema web para gestionar una empresa de servicios técnicos. Permitirá administrar clientes, equipos, órdenes de servicio, servicios, repuestos y usuarios.

El sistema tendrá autenticación mediante usuario y contraseña. Los usuarios deberán iniciar sesión para acceder al sistema.

5. AUTENTICACIÓN

El usuario ingresa:
- Email
- Contraseña

El frontend envía las credenciales a:
POST /api/auth/login

El backend valida las credenciales (hash BCrypt) y devuelve los datos del usuario:
- Id
- Nombre
- Email
- Rol

No se emite ningún token.

Para las peticiones protegidas, el frontend envía el header:
X-Usuario-Id: {id}

El backend carga el usuario desde la base de datos, verifica que esté activo y aplica su rol.

Endpoints públicos:
- POST /api/auth/login

Endpoints protegidos (requieren header X-Usuario-Id de un usuario activo):
- Clientes
- Equipos
- Órdenes
- Servicios
- Repuestos
- Usuarios
- Dashboard

10. SEGURIDAD

- Contraseñas almacenadas como hash (BCrypt).
- Autenticación mediante header X-Usuario-Id (sin token).
- El rol se toma de la base de datos, nunca del header.
- Validación de DTOs.
- CORS configurado para el frontend.
- Variables sensibles mediante configuración/variables de entorno.

11. OBJETIVO DE DESARROLLO

La aplicación debe ser sencilla de explicar y mantener. No se utilizarán microservicios, CQRS, RabbitMQ ni una Clean Architecture excesivamente compleja en la primera versión.

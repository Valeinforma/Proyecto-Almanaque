1. DESCRIPCIÓN

TechFix Manager es una aplicación web para una empresa de servicios técnicos. El sistema centraliza clientes, equipos y órdenes de reparación.

El usuario inicia sesión y luego accede al panel principal.

5. LOGIN

Pantalla dividida:

Lado izquierdo:
- Marca TechFix
- Ilustración/elementos tecnológicos
- Frase: "Organizá cada reparación desde un solo lugar."

Lado derecho:
- Email
- Contraseña
- Botón "Ingresar"
- Mensaje de error si las credenciales son incorrectas

6. DASHBOARD

Mostrar:
- Órdenes abiertas
- En diagnóstico
- En reparación
- Listas para entregar
- Ingresos estimados
- Órdenes recientes

7. CLIENTES

La pantalla tendrá:
- Buscador
- Botón Nuevo cliente
- Lista/tarjetas de clientes
- Editar
- Eliminar
- Ver equipos asociados

8. EQUIPOS

Cada equipo mostrará:
- Tipo
- Marca
- Modelo
- Número de serie
- Cliente
- Problema informado
- Estado de la orden relacionada

9. ÓRDENES

Las órdenes serán el núcleo del sistema.

Cada orden mostrará:
- Número
- Cliente
- Equipo
- Fecha de ingreso
- Problema
- Diagnóstico
- Solución
- Costo
- Estado

El estado se mostrará mediante una línea de progreso:

Recibido -> Diagnóstico -> Presupuesto -> Reparación -> Listo -> Entregado

10. API EN NEXT.JS

lib/api.ts será responsable de centralizar las solicitudes.

Ejemplo conceptual:

api.get("/clientes")
api.post("/clientes", data)
api.put("/clientes/1", data)
api.delete("/clientes/1")

En las solicitudes protegidas se enviará el header X-Usuario-Id con el id del usuario.

11. MANEJO DE SESIÓN

Al iniciar sesión:
- Backend valida las credenciales y devuelve { id, nombre, email, rol }.
- Frontend conserva el usuario en la sesión (localStorage).
- Las peticiones protegidas llevan el header X-Usuario-Id.
- Si no hay usuario o el id es inválido, se redirige a /login.

13. PRINCIPIO DE DISEÑO

El sistema debe ser visualmente moderno pero técnicamente sencillo.

Cada componente debe tener una responsabilidad clara.

14. RESPONSIVE

El sistema debe funcionar en:
- Desktop
- Notebook
- Tablet

En pantallas pequeñas, el sidebar se transforma en navegación compacta.

15. EXPERIENCIA DE USUARIO

Acciones destructivas deben solicitar confirmación.

Ejemplo:
"¿Eliminar cliente Juan Pérez?"

Los cambios exitosos mostrarán una notificación.

Los errores mostrarán un mensaje claro.

16. ESCALABILIDAD

La primera versión será monolítica:

Next.js + API .NET + PostgreSQL.

La estructura permitirá posteriormente agregar:
- notificaciones
- PDF
- fotografías
- código QR
- estadísticas
- historial de estados
- integración con email
